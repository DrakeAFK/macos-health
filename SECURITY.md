# Security policy

## Supported versions

Security fixes are made for the latest tagged release and the current
development branch. Older releases may receive a fix only when the same change
can be safely backported.

| Version | Security support |
| --- | --- |
| Latest tagged release | Supported |
| Current development branch | Pre-release fixes |
| Older releases | Best effort |

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability. Use GitHub's
private vulnerability reporting form:

<https://github.com/DrakeAFK/macos-health/security/advisories/new>

Include the affected version or commit, macOS version and hardware, reproduction
steps, expected impact, and any suggested mitigation. Remove usernames,
hostnames, IP addresses, process details, crash dumps, or other personal data
that are not necessary to reproduce the issue.

The maintainers will acknowledge a complete report, assess its severity, and
coordinate a fix and disclosure. Please allow time for users to receive a fixed
release before publishing exploit details.

## Security model

`macos-health` is a read-only local dashboard. During normal metric collection
it:

- does not require or invoke `sudo`;
- does not require Full Disk Access;
- does not initiate outbound network connections;
- does not upload analytics, crash data, or metric telemetry;
- does not install a daemon, agent, kernel extension, or login item;
- invokes a small set of Apple system tools by absolute path with fixed locale;
- uses read-only Darwin `libproc`, IOReport, and AppleSMC/HID APIs when the
  optional native sensors are enabled;
- reads process executable names, start identity, PIDs, and parent PIDs, never
  full argument lists or process environments.

The tool is not a security boundary. Any user able to read the terminal or an
exported snapshot can see its unredacted contents. Computer name, hostname,
local addresses, process names, and PIDs can be sensitive. Use redacted output
and review files before sharing them.

Metric text is treated as untrusted terminal input and should be stripped of
control sequences before rendering. Reports involving terminal escape
injection, command execution, parser denial of service, privilege escalation,
unsafe temporary files, or release artifact substitution are in scope.

## Native telemetry

The optional `--sensors` backend uses read-only, capability-tested IOReport and
AppleSMC/HID interfaces for CPU/GPU/ANE energy, GPU residency, temperatures,
and fan RPM. These are private Apple APIs and can change between hardware and
macOS releases; failures are isolated and shown as unavailable. The backend
never invokes `sudo`, `powermetrics`, or a privileged helper. Disable it with
`--sensors=false` when a fully public API surface is preferred.

## Release integrity

Tagged releases contain architecture-specific archives and a SHA-256
`checksums.txt` generated by GoReleaser in GitHub Actions. After downloading an
archive, calculate its digest locally:

```sh
shasum -a 256 macos-health_VERSION_darwin_ARCH.tar.gz
```

Compare the complete digest and filename with the corresponding line in
`checksums.txt` from the same GitHub release. Stop if they differ. Release
archives are not currently promised to be Apple-notarized; macOS quarantine or
Gatekeeper behavior is separate from the privacy permissions used for metric
collection.
